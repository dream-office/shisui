# 路线图

> 这份清单说明**想做什么**，以及**明确不做什么**。有想法请开 Issue 讨论，不要直接动手写大功能。

## 定位

一个**打开即用、零配置、数据不出本机**的群消息截止时间管理器。核心价值只有一句话：
把口语化的通知变成绝对时间，并在撞车之前提醒你。公司群、项目群、班级群、家长群，同一套规则。

它不打算变成「全能日程应用」——那是原生 App + 云端同步的战场，
而本项目的技术选择（纯前端、IndexedDB、无账号）恰好是另一条路线。

## 明确不做（非目标）

| 不做 | 原因 |
| --- | --- |
| 账号体系与云同步 | 一旦有后端，隐私卖点消失，运维成本也上来。需要同步的用户可以导出 JSON 自行处理。 |
| 系统通知 / 推送 | 需要申请权限、打断体验，且移动端限制多。当前策略是「打开就看到」。 |
| 原生移动 App | Web 已经够快；包一层反而增加维护面积。 |
| 通用聊天 / 群管理 | 超出范围。只做「通知 → 待办」这一条链路。 |

## 优先级原则

1. **解析错的 bug** 优先于一切——这是产品的地基。
2. **影响主路径**（粘贴 → 解析 → 收录 → 日程）的易用性问题优先。
3. 已经写进[设计记录](DEVLOG.md)的约束如果要改，先改文档再改代码。
4. 新能力排在最后：宁可少一个功能，不要多一处「说不清为什么这么判」的逻辑。
