# 课代表 · 群消息变日程

> 把班级群/辅导员通知粘进来，10 秒解析成不会错过的日程，并告诉你哪两件事会撞车。

纯前端、本地优先、无后端、无账号。数据只存在你自己的浏览器里。

---

## 1. 它解决什么问题

大学生的截止时间散落在 QQ 群、班级群、辅导员私聊、教务通知、学习通公告里，形式是这种：

```
【教务处】各位同学请注意：
1. 本周五23:59前，请在学习通提交《数据结构》实验报告三，逾期系统自动关闭。
2. 下周三下午2点，在 教学楼A301 召开选题班会，请准时参加。
3. 11月18日前完成课程设计答辩PPT，发送至 teacher@edu.cn。
4. 请大家3天内完成校园学习生活问卷，链接见群公告。
```

人眼扫一遍要 30 秒，还得自己在脑子里换算「本周五」是哪天、有没有跟别的事撞上。**错过一次实验报告，代价是平时分。**

课代表做的事：把这段话变成 4 条带绝对时间的待办，并当场告警——「两件事几乎同时截止」「这一天堆了 3 件事」。

**和「AI 套壳应用」的区别**：核心难点不是调模型，而是中文口语时间的确定性归一化（「本周五23:59」「下周三之前」「明晚8点」「3天内」），这部分用规则引擎实现，可解释、可离线、可单测；大模型是叠加在上面的增强层，不是唯一路径。

## 2. 10 分钟极速复现

### 前置条件

| 项目 | 要求 | 验证命令 |
| --- | --- | --- |
| Node.js | ≥ 18（开发时用 24.21.0） | `node -v` |
| 包管理器 | pnpm ≥ 9（开发时用 11.28.5），npm 也可 | `pnpm -v` |
| 浏览器 | Chrome / Edge / Safari 新版（需 IndexedDB） | — |
| 网络 | 仅首次安装依赖需要 | — |

### 三步跑起来

```bash
# 1. 安装依赖（首次约 1-2 分钟）
pnpm install

# 2. 启动开发服务器
pnpm dev

# 3. 打开浏览器访问
#    http://127.0.0.1:5173
```

> 用 npm 的等价写法：`npm install && npm run dev`（本仓库锁文件为 pnpm-lock.yaml，npm 会自行解析依赖树）。

### 验收清单（照着点，2 分钟验完）

1. **打开就不报错**：页面标题「课代表 · 群消息变日程」，右上角显示「规则引擎」。
2. **不配任何 Key 也能用**：这是硬要求——读者复现不该被 API Key 卡住。
3. **点「填入示例一」→「开始解析」**：出现 4 张候选卡片，分别是作业 / 会议 / 考试 / 问卷。
4. **核对时间**：
   - 第 1 条：`本周五 23:59`（相对当前日期换算成绝对时间）
   - 第 2 条：地点识别为「教学楼A301」，类型「会议」
   - 第 3 条：渠道识别为「邮箱」，截止 `11月18日 23:59`
   - 第 4 条：「3天内」换算成 3 天后的 `23:59`
5. **点某张卡片的「为什么这么判断」**：能看到命中的时间短语、关键词、渠道、置信度理由。
6. **「全部收录」→ 切到「日程」**：看到 7 天压力条、按天分组的待办、每条右侧的倒计时。
7. **制造一次冲突**：把两条待办的时间改成相差 30 分钟，日程页会立刻出现「两件事几乎同时截止」告警。
8. **刷新页面**：数据还在（IndexedDB 持久化）。
9. **跑测试**：`pnpm test` → `48 passed`。

### 可选：启用 AI 双引擎

设置页填入任意 OpenAI 兼容接口（接口地址 / 模型 / API Key），保存后右上角变成「双引擎」。
解析时会实时显示「AI 正在阅读通知… 已收 xxx 字」，AI 输出完成后再与规则结果合并。
**不填也完全可用**，只是对特别绕的写法容错低一些。

## 3. 依赖清单

运行时会用到的全部依赖（其余均为构建期工具）：

| 依赖 | 版本 | 用途 | 是否可替代 |
| --- | --- | --- | --- |
| react / react-dom | 18.3.1 | 视图层 | — |
| zustand | 5.0.16 | 状态编排，避免 prop drilling | Context API 也可 |
| dexie | 4.4.7 | IndexedDB 封装 | 原生 IndexedDB 也可 |

构建与测试：`vite 6`、`typescript 5.9`（strict）、`vitest 3`、`@vitejs/plugin-react`。

**没有 UI 框架**（不用 Ant Design / Tailwind），样式是手写的 CSS 变量体系：`src/styles.css`。
理由：这类小工具引入组件库会让包体翻三倍，且视觉容易撞脸。

环境变量：**本项目不需要任何环境变量**（AI Key 存在浏览器 localStorage，不写进代码库）。
这是刻意设计——`.env` 是复现失败的第一大来源。

## 4. 目录结构与分层

```
src/
├─ core/                  ← 纯领域逻辑：零 React、零 IO、可 100% 单测
│  ├─ types.ts            领域类型（ParsedTask / StoredTask / ImportBatch）
│  ├─ time.ts             ★ 中文时间表达归一化引擎
│  ├─ ruleParser.ts       ★ 通知切分与待办抽取（规则引擎）
│  ├─ conflict.ts         ★ 冲突体检与 7 天压力分布
│  ├─ merge.ts            规则 + AI 双引擎合并
│  ├─ format.ts           时间的人话渲染与倒计时
│  └─ samples.ts          示例通知（UI 演示与单测共用同一份）
├─ data/                  ← 持久化
│  ├─ db.ts               Dexie schema
│  └─ repo.ts             仓储层：UI 不直接碰 Dexie
├─ services/
│  └─ llm.ts              AI 引擎：Prompt、流式 SSE、JSON 解析、降级
├─ state/
│  └─ store.ts            业务流编排：解析 → 合并 → 确认 → 落库
├─ ui/                    ← 视图组件（只读状态、调 action）
└─ styles.css             手写样式与设计变量
```

**为什么这么切**：AI 生成代码最典型的失败是「一个 800 行的 App.tsx 什么都干」。这里的约束是单向依赖——

```
ui → state → data / services → core
```

`core` 不 import 任何上层模块，所以它能被单测完整覆盖；`ui` 不含业务分支，所以改视觉不改逻辑。

## 5. 三个核心设计

### 5.1 时间归一化：注入 `ref` 的纯函数

```ts
extractTime('本周五23:59前提交实验报告', new Date(2026, 10, 4, 22, 7))
// → { atMs: 2026-11-06 23:59, isDeadline: true, ambiguous: false, ... }
```

「现在」是参数而不是 `Date.now()`，因此任何时刻调用都得到同一结果。这条设计让 48 条测试全部确定性通过——**换机器、换时区、明年再跑，结果不变**。这是「可复现」从口号变成工程事实的关键一步。

覆盖的时间表达：`本周五` `下周三` `下下周一` `周五` `今天/明天/后天/大后天` `明晚` `11月18日` `11/18` `2026-11-18` `3天内` `八点半` `23:59` `下午2点` `中午12点` `凌晨`。

**歧义绝不静默处理**：光说「8点」不知道上午下午、已经过去的月日按明年算、只有钟点没有日期——这些都会标 `ambiguous: true`，在 UI 里降为低置信度并要求人工确认。

### 5.2 双引擎：规则保底，AI 补全

```
通知原文 ─┬─→ 规则引擎（可解释、离线、快） ──┐
          └─→ AI 引擎（覆盖刁钻写法、慢）  ──┴→ mergeTasks() → 候选卡片
```

合并策略刻意保守：
- 规则引擎命中的时间**优先保留**（它的换算过程可解释）；
- 两引擎对上的条目 → 置信度取高者，标记「双引擎一致」；
- AI 独有的条目 → **置信度封顶 medium**，理由里注明「请重点核对」——无法解释的结论不配高置信。

AI 请求 `temperature: 0`，流式读取，把「正在读 / 正在写 N 字」的中间态直接显示在界面上，而不是一个转圈黑盒。

### 5.3 冲突体检：从「知道了」到「省心了」

只解析不体检，产品价值少一半。收录后自动扫描：

| 检查 | 触发条件 | 展示 |
| --- | --- | --- |
| 已过期 | 截止时间早于现在 | 红色行 + 独立告警 |
| 撞车 | 两条截止相差 ≤ 2 小时 | 黄色告警 |
| 堆积 | 同一天 ≥ 3 件 | 黄色告警 |
| 压力 | 未来 7 天每天件数 | 柱状压力条 |

## 7. 隐私

- 没有后端，**没有任何网络请求**（除非你主动配置了 AI 引擎，此时请求直接发给你填的服务商）。
- 数据存在浏览器 IndexedDB，清浏览器数据即彻底删除。
- 支持导出 JSON 备份（设置页），导出文件你自己保管。

班级群通知里常有学号、手机号、成绩，这个设计不是「省事」，是必需。

## 8. 已知限制

1. **跨天/跨月边界**：「本周日」在周日当天解析为当天，不自动顺延到下周（已在 UI 标歧义）。
2. **多事项复合句**：一句话里塞三件事（「交报告、报名、开会」）目前会合并成一条，需人工拆。
3. **图片通知**：暂不支持截图/OCR，只接受文本粘贴。
4. **AI 引擎**：依赖外部服务，接口不可用时自动降级到规则引擎（已实现并在 UI 提示）。
5. **无提醒推送**：当前是「打开就看到」，不做系统通知（避免申请权限打断体验）。
